# 24R 已选定的交互设计

原生第一版已接入 Companion；使用、验证与当前边界见 [24R 实现说明](../../24r.md)。本目录仍为静态设计原型。

用户已选择 A 时间线首页，结合 C 的行动日报。当前是交互原型，尚未连接录音、模型、Quenda 或同步服务。
旧的三个方向留在 `explorations-v1.html` 作为设计来源，包含旧留存规则，仅供回顾。当前规则以下文为准。

运行（quenda-companion 根目录）：

```sh
python3 -m http.server 8764 --bind 127.0.0.1 --directory docs/prototypes/24r
```

打开 http://127.0.0.1:8764/?device=mac&page=settings 。可切换手机/电脑、首页/日报/历史/设置。
所有配置和演示片段只存在内存中，刷新重置；API Key 输入禁用，不接收真实密钥。

## 原型阶段的音频策略（历史记录）

以下为当时的设计，不代表当前实现。0.5.0 已改为待转写片段持久暂存、重连补传；正式行为见 [24R 说明](../../24r.md)。

- 默认不持久化原始音频。音频块只在转写所需的短期内存中存在，处理后释放；文字、小时摘要、日报双端保存。
- 用户点“保留音频”，或开启关键词功能并命中明确的可配置短语后，才开始保留后续声音。
- 不默认回溯触发前的声音，不把泛化的“危险识别”当成可靠触发依据。
- 保留中必须始终有明显状态和停止按钮。默认单次上限 5 分钟，可选 1/5/15 分钟；暂停记录也结束保存。
- 保留片段默认只在 iPhone，用户可播放、导出和删除；不送入云端文字模型。音频备份策略尚待后续明确。
- 当前设计依赖 Mac 转写：断开后自动转写暂停，未主动保存的离线音频不补传；手动保留仍需可用。关键词离线可用性必须以设备识别能力为准。
- 实现时不得走 Whisper Anywhere 自动生成 LastInput.wav 的诊断路径；临时 WAV、日志、崩溃附件也不能绕过留存策略。

## 智能整理

三个可替换的分析执行方式：

1. 本地 Ollama：Mac 可访问的服务地址、已安装模型、测试连接、模型驻留时间。127.0.0.1 指配对的 Mac，不是 iPhone。
2. 云端直连：Provider / API 协议、Base URL、模型、API Key（正式实现写入 Mac 钥匙串）。只发送用于整理的文字和选定历史。
3. Quenda Agent：24R 专属 Agent ID、跟随 Agent Provider 或为专属 Agent 指定 Provider/模型。复用已有 Gateway 连接，不启动/停止独立 Gateway，不擅自修改其他 Agent。

Ollama 可用空请求预加载模型，并通过 keep_alive 控制驻留。每小时整理默认空闲 5 分钟释放，避免持续占用语音识别所需内存；可选择常驻。
官方依据：https://docs.ollama.com/faq （preload / keep_alive），模型列表：https://docs.ollama.com/api/tags 。

## 历史关联

直接模型模式由 24R 提供相关历史日报和未完成事项。Quenda 模式还可关联选定项目，默认仅 24R 项目、最近 30 天；相关结论展示日期与来源。
不能仅通过“选一个 Agent”就假定它能读取所有旧会话。正式接入需实现或确认历史检索工具、项目范围和引用返回，保留当日事实与历史推断的区别。
先检索相关片段，再结合当日文字分析，避免整份历史无界注入。

## 验证范围

可操作流程：手动保留/停止、暂停结束保留、关键词模拟触发、演示片段列表与删除、三种分析方式、Agent/Provider/模型/历史范围、离线提示。
后台录音、触发词识别、实际模型调用、历史检索、同步和耗电尚未实现，须在原生实现和实机测试后验证。
